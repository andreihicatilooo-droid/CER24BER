# CERBER Telegram Bot

Асинхронный Telegram-бот магазина CERBER на Python.  Бот отправляет `START.jpg` при первом сообщении, создаёт пользователя в базе при `/start`, строит пользовательскую витрину поверх GiftAPI, ведёт локальный баланс, платежи, заказы и гарант-сделки между пользователями с блокировкой средств, внутренним чатом, диспутами и запросами вывода в USDT.

## Возможности

| Раздел | Что делает |
|--------|-----------|
| Витрина | Категории, товары, поиск, пагинация, карточка товара, покупка SKU |

## Быстрый запуск

```powershell
# 1. Клонируйте репозиторий и создайте venv
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 2. Установите зависимости
pip install -e .[dev]

# 3. Скопируйте шаблон конфигурации и заполните BOT_TOKEN
copy .env.example .env
# Откройте .env и вставьте токен бота от @BotFather

# 4. Положите START.jpg в корень проекта (необязательно)

# 5. Запустите бота
python -m cerber_bot
```

Бот автоматически создаст SQLite-базу в `data/cerber.db` при первом запуске.

## Витрина магазина

При первом открытии витрины бот загружает каталог из GiftAPI (категории + товары + прайс-лист) и кэширует его на `CATALOG_CACHE_TTL` секунд.

- **Категории** сортируются по количеству товаров, пустые скрываются.
- **Товары** показывают диапазон цен, остатки, количество SKU.
- **Карточка товара** содержит описание, обязательные поля заказа и список SKU с кнопками `[Купить]`.
- **Покупка**: бот создаёт заказ через GiftAPI, списывает стоимость с баланса, сохраняет заказ в БД и показывает delivery data (коды, ключи и т.д.).

## Кошелёк и платежи

Бот ведёт персональный баланс для каждого пользователя:

| Поле | Описание |
|------|----------|
| `balance` | Доступные средства |
| `held_balance` | Заблокированные (сделки + заявки на вывод) |
| `balance_currency` | Валюта кошелька |

**Пополнение через NicePay:**

1. Пользователь выбирает сумму (+10 / +25 / +50 / +100 или произвольную).
2. Бот создаёт pending-платёж в БД и запрашивает у NicePay ссылку.
3. Пользователь переходит по ссылке и оплачивает.
4. NicePay отправляет callback на публичный URL `{WEB_BASE_URL}/webhooks/nicepay`.
5. Бот проверяет подпись, сумму, валюту и зачисляет средства.
6. Пользователь получает уведомление в Telegram.

Если `PAYMENTS_CURRENCY` ≠ `WALLET_CURRENCY`, суммы конвертируются через ExchangeRateService.

## Гарант-сделки

Полноценный escrow со следующим потоком:

1. **Покупатель** указывает продавца, сумму и условия.
2. Сумма **блокируется** на балансе покупателя (`balance → held_balance`).
3. Продавец получает уведомление и может **принять** или **отклонить**.
4. После принятия открывается **чат сделки** — сообщения, фото, файлы пересылаются через бота.
5. Покупатель подтверждает выполнение → средства **зачисляются продавцу**.
6. Любая сторона может **открыть диспут** или **позвать модератора**.
7. Модератор принимает решение: **возврат покупателю** или **зачисление продавцу**.

Все операции записываются в `wallet_transactions` и `escrow_deal_messages`.

## Вывод в USDT

1. Пользователь вводит сумму в USDT.
2. Выбирает сеть из `WITHDRAWAL_NETWORKS` (TRC20, BEP20, ERC20).
3. Отправляет адрес кошелька.
4. Сумма блокируется, модератор получает уведомление.
5. Модератор одобряет → статус «approved» (средства не возвращаются).
6. Модератор отклоняет → средства автоматически возвращаются на баланс.

## GiftAPI-раздел

Отдельный раздел бота для прямой работы с партнёрским сервисом GiftAPI:

- Профиль партнёра и баланс
- Список категорий
- Список товаров
- Поиск товара по UUID
- Список заказов
- Поиск заказа по UUID
- Создание заказа через JSON
- Статус eSIM по ICCID

Доступен через кнопку «GiftAPI» или callback `giftapi:menu`.

## Провайдеры каталога

Система каталога расширяемая.  Каждый провайдер реализует интерфейс `CatalogProvider`:

| Провайдер | Источник | Когда подключается |
|----------|---------|-------------------|
| `DemoCatalogProvider` | Тестовые товары | `ENABLE_DEMO_PROVIDER=true` |
| `GiftApiCatalogProvider` | GiftAPI `/catalog` | `ENABLE_GIFTAPI_PROVIDER=true` + `GIFTAPI_TOKEN` |
| `RestCatalogProvider` | `GET /products` | `REST_PROVIDER_URL` задан |
| `WarehouseCatalogProvider` | `GET /inventory` | `WAREHOUSE_PROVIDER_URL` задан |

Подробнее о создании своего провайдера — в [EXTENDING.md](EXTENDING.md).

## Web-приложение

Помимо Telegram-бота, проект включает **веб-интерфейс** на FastAPI + Jinja2 + Tailwind CSS,
который дублирует весь функционал бота и работает параллельно с ним.

### Запуск

По умолчанию веб-приложение стартует вместе с ботом на порту `8088`.
Управление через `.env`:

```env
WEB_ENABLED=true     # включить/выключить веб
WEB_HOST=0.0.0.0     # адрес привязки
WEB_PORT=8088         # порт
```

После запуска бота откройте `http://localhost:8088`.

### Авторизация

- **Production**: Telegram Login Widget (`/login/callback` с HMAC-SHA256 проверкой)
- **Разработка**: демо-вход по адресу `/demo-login` (создаёт пользователя с `telegram_id=1`)

### Разделы веб-интерфейса

| Раздел | URL | Описание |
|--------|-----|----------|
| Витрина | `/store` | Каталог товаров, категории, поиск, покупка |
| Кошелёк | `/wallet` | Баланс, история транзакций, пополнение через NicePay |
| Заказы | `/orders` | Список заказов и детали доставки |
| Сделки | `/deals` | Escrow-сделки, чат, вывод USDT |
| Профиль | `/profile` | Информация о пользователе и статистика |

### Архитектура

Веб-приложение **использует те же сервисы**, что и бот (`StoreService`, `DealService`,
`PaymentService` и т.д.), без дублирования бизнес-логики. Сессии хранятся в cookie
(`cerber_session`, подписана `bot_token`, TTL 7 дней).

## Troubleshooting

### `Could not find platform independent libraries <prefix>`

Это не ошибка кода бота. Это признак поврежденной системной установки Python или виртуального окружения, из которого запущен проект. В текущем репозитории это предупреждение подавить нельзя, потому что оно печатается самим интерпретатором еще до старта приложения.

Что делать:

1. Переустановить нормальный Python для Windows.
2. Пересоздать `.venv` на исправном интерпретаторе.
3. Переустановить зависимости через `pip install -e .[dev]`.

### `ClientConnectorError: Cannot connect to host api.telegram.org:443`

Это уже внешняя сетевая проблема: Telegram API недоступен из вашей среды. Бот теперь стартует и логирует такие случаи аккуратнее, без лишнего traceback на этапе `delete_webhook`, но сам доступ к `api.telegram.org` все равно обязателен.

Проверьте:

1. Есть ли доступ к `api.telegram.org:443` с машины.
2. Не режет ли соединение firewall, антивирус, прокси или VPN.
3. Нет ли проблем у провайдера или маршрута до Telegram.

### `TelegramConflictError: terminated by other getUpdates request`

Это значит, что одновременно запущено два polling-процесса одного и того же бота. Telegram позволяет только один активный `getUpdates` consumer.

Что делать:

1. Остановить все лишние процессы с этим ботом.
2. Оставить только один активный запуск `python -m cerber_bot`.
3. Если бот уже крутится где-то на сервере, локальный polling нужно выключить.

### Пополнение не работает и бот пишет про `NICEPAY_MERCHANT_ID` или `NICEPAY_SECRET`

Это значит, что NicePay flow уже включен в коде, но не настроен в окружении.

Что нужно:

1. Создать и настроить мерчанта NicePay.
2. Указать `NICEPAY_MERCHANT_ID` и `NICEPAY_SECRET` в `.env`.
3. Настроить callback URL мерчанта на публичный путь `{WEB_BASE_URL}/webhooks/nicepay` вашего сервера.
4. Если валюты отличаются, убедиться, что работает `EXCHANGE_RATE_API_URL` или задан `FALLBACK_USDT_RUB_RATE`.

### Споры и выводы не доходят до модератора

Это значит, что бот не знает, кому слать внутренние уведомления.

Что нужно:

1. Указать `MODERATOR_IDS` через запятую.
2. Убедиться, что модераторы уже открывали диалог с ботом.
3. Если `MODERATOR_IDS` не заданы, бот оставит сценарий рабочим, но спор и вывод придется разбирать вручную через поддержку.
